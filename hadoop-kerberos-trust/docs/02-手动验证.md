# 手动分步操作（学习/对照用）

> 正常使用请直接执行 `scripts/01-init-kdc.sh`、`02-start-hdfs.sh`、`03-verify.sh`。
> 本文档把脚本内部做的每一步手工拆开，便于理解"双 KDC 互信"到底做了什么，
> 也可作为脚本出问题时的排查对照。

## 第 0 步：构建并启动双 KDC

```bash
cd kerberos
docker compose up -d --build     # 或 docker-compose up -d --build
```

此时 kdc1（EMR.1234.COM）与 kdc2（EMR.6789.COM）已启动，各自初始化了 KDC 数据库。

## 第 1 步：在 kdc1 上建立互信并创建 principal

```bash
docker exec -it kdc1 bash

# 1.1 建立双向互信（两个方向的 krbtgt，密码必须一致=123456）
kadmin.local -q "addprinc -pw 123456 krbtgt/EMR.6789.COM@EMR.1234.COM"
kadmin.local -q "addprinc -pw 123456 krbtgt/EMR.1234.COM@EMR.6789.COM"
kadmin.local -q "getprinc krbtgt/EMR.6789.COM@EMR.1234.COM"   # 核对
kadmin.local -q "getprinc krbtgt/EMR.1234.COM@EMR.6789.COM"

# 1.2 HDFS / YARN 服务 principal（随机密钥）
kadmin.local -q "addprinc -randkey nn/namenode.emr.1234.com@EMR.1234.COM"
kadmin.local -q "addprinc -randkey dn/datanode.emr.1234.com@EMR.1234.COM"
kadmin.local -q "addprinc -randkey HTTP/namenode.emr.1234.com@EMR.1234.COM"
kadmin.local -q "addprinc -randkey HTTP/datanode.emr.1234.com@EMR.1234.COM"
kadmin.local -q "addprinc -randkey rm/resourcemanager.emr.1234.com@EMR.1234.COM"
kadmin.local -q "addprinc -randkey nm/nodemanager.emr.1234.com@EMR.1234.COM"

# 1.3 本地测试用户
kadmin.local -q "addprinc -pw 123456 test"

# 1.4 导出 keytab（nn.keytab 同时含 nn 与 HTTP 两个 principal）
kadmin.local -q "xst -k /root/nn.keytab nn/namenode.emr.1234.com HTTP/namenode.emr.1234.com"
kadmin.local -q "xst -k /root/dn.keytab dn/datanode.emr.1234.com HTTP/datanode.emr.1234.com"
kadmin.local -q "xst -k /root/rm.keytab rm/resourcemanager.emr.1234.com"
kadmin.local -q "xst -k /root/nm.keytab nm/nodemanager.emr.1234.com"
kadmin.local -q "xst -norandkey -k /root/test.keytab test"
chmod 400 /root/*.keytab
exit
```

## 第 2 步：在 kdc2 上建立互信并创建 principal（对称操作）

```bash
docker exec -it kdc2 bash

kadmin.local -q "addprinc -pw 123456 krbtgt/EMR.6789.COM@EMR.1234.COM"
kadmin.local -q "addprinc -pw 123456 krbtgt/EMR.1234.COM@EMR.6789.COM"

kadmin.local -q "addprinc -randkey nn/namenode.emr.6789.com@EMR.6789.COM"
kadmin.local -q "addprinc -randkey dn/datanode.emr.6789.com@EMR.6789.COM"
kadmin.local -q "addprinc -randkey HTTP/namenode.emr.6789.com@EMR.6789.COM"
kadmin.local -q "addprinc -randkey HTTP/datanode.emr.6789.com@EMR.6789.COM"
kadmin.local -q "addprinc -randkey rm/resourcemanager.emr.6789.com@EMR.6789.COM"
kadmin.local -q "addprinc -randkey nm/nodemanager.emr.6789.com@EMR.6789.COM"

kadmin.local -q "addprinc -pw 123456 test1"

kadmin.local -q "xst -k /root/nn.keytab nn/namenode.emr.6789.com HTTP/namenode.emr.6789.com"
kadmin.local -q "xst -k /root/dn.keytab dn/datanode.emr.6789.com HTTP/datanode.emr.6789.com"
kadmin.local -q "xst -k /root/rm.keytab rm/resourcemanager.emr.6789.com"
kadmin.local -q "xst -k /root/nm.keytab nm/nodemanager.emr.6789.com"
kadmin.local -q "xst -norandkey -k /root/test1.keytab test1"
chmod 400 /root/*.keytab
exit
```

## 第 3 步：把 keytab / krb5.conf 分发到 hdfs 目录

```bash
# 集群 A（来自 kdc1）
mkdir -p hdfs/kerberos hdfs/kerberos1
docker cp kdc1:/root/nn.keytab      hdfs/kerberos/nn.keytab
docker cp kdc1:/root/dn.keytab      hdfs/kerberos/dn.keytab
docker cp kdc1:/root/rm.keytab      hdfs/kerberos/rm.keytab
docker cp kdc1:/root/nm.keytab      hdfs/kerberos/nm.keytab
docker cp kdc1:/root/test.keytab    hdfs/kerberos/test.keytab
docker cp kdc1:/etc/krb5.conf       hdfs/kerberos/krb5.conf

# 集群 B（来自 kdc2）
docker cp kdc2:/root/nn.keytab      hdfs/kerberos1/nn.keytab
docker cp kdc2:/root/dn.keytab      hdfs/kerberos1/dn.keytab
docker cp kdc2:/root/rm.keytab      hdfs/kerberos1/rm.keytab
docker cp kdc2:/root/nm.keytab      hdfs/kerberos1/nm.keytab
docker cp kdc2:/root/test1.keytab   hdfs/kerberos1/test1.keytab
docker cp kdc2:/etc/krb5.conf       hdfs/kerberos1/krb5.conf
```

## 第 4 步：启动双 HDFS 集群

```bash
cd hdfs
docker compose -p hdfs-a -f docker-compose.yml up -d      # 集群 A（EMR.1234.COM）
docker compose -p hdfs-b -f docker-compose-1.yml up -d    # 集群 B（EMR.6789.COM）
```

## 第 5 步：容器内安装 krb5-user（首次需要）

bde2020 的 Hadoop 镜像基于 Debian，默认没有 `kinit`/`klist`：

```bash
docker exec -it namenode bash
echo "deb http://archive.debian.org/debian stretch main contrib non-free" > /etc/apt/sources.list
echo "deb http://archive.debian.org/debian-security stretch/updates main contrib non-free" >> /etc/apt/sources.list
echo "Acquire::Check-Valid-Until false;" > /etc/apt/apt.conf.d/99no-check-valid-until
apt-get update && apt-get install -y krb5-user
```

namenode1 同样操作。

## 第 6 步：双向跨域验证

```bash
# 集群 A 视角（namenode，用户 test@EMR.1234.COM）
docker exec -it namenode bash
kinit -kt /root/test.keytab test
klist                                   # 应看到本域 TGT
hdfs dfs -ls hdfs://namenode.emr.1234.com:9000/user    # 本域访问
hdfs dfs -ls hdfs://namenode.emr.6789.com:9000/user    # ★ 跨域访问集群 B

# 集群 B 视角（namenode1，用户 test1@EMR.6789.COM）
docker exec -it namenode1 bash
kinit -kt /root/test1.keytab test1
hdfs dfs -ls hdfs://namenode.emr.6789.com:9000/user    # 本域访问
hdfs dfs -ls hdfs://namenode.emr.1234.com:9000/user    # ★ 跨域访问集群 A
```

跨域访问成功后，再执行 `klist` 可以看到新增的跨域 TGT
（`krbtgt/EMR.6789.COM@EMR.1234.COM` 或 `krbtgt/EMR.1234.COM@EMR.6789.COM`）
以及目标集群的服务票据，这就是互信生效的直接证据。

## 第 7 步：清理

```bash
cd hdfs
docker compose -p hdfs-a -f docker-compose.yml down -v
docker compose -p hdfs-b -f docker-compose-1.yml down -v
cd ../kerberos
docker compose down -v
docker network rm hadoop-kerberos-net
```
