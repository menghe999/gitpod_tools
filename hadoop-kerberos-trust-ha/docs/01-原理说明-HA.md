# 01. HDFS HA 原理与跨域互信的结合（最小 HA 版）

## 1. HDFS NameNode 高可用的三个组件

NameNode 是 HDFS 的单点（元数据全在内存 + 编辑日志），HA 要解决"**元数据不丢**"和"**故障自动切换**"两件事：

| 组件 | 作用 | 本方案 |
|---|---|---|
| **双 NameNode**（active/standby） | active 提供服务；standby 实时追平状态，随时可接管 | 每集群 2 台（nn1/nn2） |
| **JournalNode（QJM）** | 共享编辑日志：active 把每次元数据变更同步写到多数 JN（仲裁 2/3），standby 从 JN 回放追平；active 宕机后新 active 从 JN 恢复，元数据不丢 | 3 台共享（jn1/jn2/jn3） |
| **ZooKeeper + ZKFC** | 自动故障转移：每个 NN 上跑 ZKFC，通过 ZK 锁决定谁是 active；检测到 active 失联（ZK 会话超时）→ 隔离旧 active → standby 接管 | 单节点 zk1 + 每 NN 一个 ZKFC |

**数据路径**：
```
客户端 → hdfs://ns1234（nameservice）→ ConfiguredFailoverProxyProvider → 当前 active NN
active NN 写编辑日志 → qjournal://jn1:8485;jn2:8485;jn3:8485/ns1234（≥2 台确认）
standby NN ← 从 QJM 回放编辑日志，保持与 active 一致
```

## 2. 首次初始化流程（start-nn.sh 自动完成）

1. **nn1**：`hdfs namenode -format`（同时初始化 QJM 命名空间）→ 启动 NN → `hdfs zkfc -formatZK`
   （在 ZK 创建 `/hadoop-ha/ns1234` 节点）→ 启动 ZKFC → NN 退出安全模式后成为 **active**；
2. **nn2**：等待 nn1 成为 active → `hdfs namenode -bootstrapStandby`（从 active 下载 fsimage）→
   启动 NN → 启动 ZKFC → 发现 nn1 持有锁 → 成为 **standby**（之后通过 QJM 持续追平）；
3. **重启幂等**：name dir 已存在则跳过 format/bootstrap，直接启动 NN + ZKFC；
   若对端已是 active，本节点自动以 standby 身份加入。

## 3. 故障转移过程

1. 停止 active NN（容器停止 → 其 ZKFC 的 ZK 会话超时）；
2. standby 侧的 ZKFC 检测到锁释放 → 对旧 active 执行隔离（`dfs.ha.fencing.methods=shell(true)`，
   演示环境不做真实隔离）→ 获取锁 → `transitionToActive`；
3. 新 active 从 QJM 回放编辑日志到最新 → 开始服务；
4. 客户端通过 nameservice 代理自动重连新 active（无需改配置）；
5. 原 NN 重启后自动以 standby 身份回归（数据路径经 QJM 同步，无丢失）。

## 4. 与跨域互信的结合

- **JN 跨域**：3 台 JN 位于 `EMR.1234.COM` realm（主体 `jn/jn1|jn2|jn3.emr.1234.com`）。
  集群 B 的 NN 连接 JN 时，按 `dfs.journalnode.kerberos.principal=jn/_HOST@EMR.1234.COM`
  构造服务主体，经双 KDC 跨域互信换票（与普通跨域 HDFS 访问同一套机制）；
- **双 NN 各自的 Kerberos 主体**：`nn/_HOST@<REALM>` 按容器主机名自动展开
  （nn1.emr.1234.com → `nn/nn1.emr.1234.com@EMR.1234.COM`），每台 NN 使用独立 keytab
  （nn1.keytab / nn2.keytab），HTTP 主体同理；
- **客户端跨域**：`test@EMR.1234.COM` 访问 `hdfs://nn1.emr.6789.com:9000` 时，
  经 kdc1 换跨域 TGT（`krbtgt/EMR.6789.COM@EMR.1234.COM`）→ 去 kdc2 换取
  `nn/nn1.emr.6789.com@EMR.6789.COM` 服务票据 → 认证访问集群 B。

## 5. 最小化的取舍（与生产的差距）

| 项 | 本方案 | 生产建议 |
|---|---|---|
| ZooKeeper | 单节点（ZK 自身单点） | 3 节点仲裁 |
| DataNode | 每集群 1 台（无冗余，replication=1） | ≥3 台，replication=3 |
| 隔离方法 | `shell(true)`（不做真实隔离） | sshfence / 脚本真实隔离 |
| 跨域客户端 | 显式 NN 地址 | 客户端配置远端 nameservice（proxy 容错） |
| Web UI | HTTP_ONLY（为简化 bootstrapStandby） | HTTPS + SPNEGO |
