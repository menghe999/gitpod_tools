# 02. 手动验证（HA 版）

以下命令在**任意一台 NameNode 容器**内执行（例如 `namenode-a1`），前提是已执行
`scripts/01-init-kdc.sh` 与 `scripts/02-start-hdfs.sh`。

> **kinit 说明**：所有容器（ZK/JN/NN/DN/RM/NM/flink-client）启动时会**后台自动补装**
> krb5-user（`kinit`，见 FAQ Q13 的"补装机制"），因此下面的 `kinit` 命令直接可用；
> 若容器刚启动或网络不佳，稍等片刻，或手动补装：
> `docker exec <容器> bash /root/install-krb5.sh`（kdc1/kdc2 已内置 krb5-workstation）。

## 1. 查看 HA 状态

```bash
docker exec namenode-a1 bash -c 'kinit -kt /root/test.keytab test && hdfs haadmin -ns ns1234 -getServiceState nn1 && hdfs haadmin -ns ns1234 -getServiceState nn2'
# 期望输出：
# active
# standby

docker exec namenode-b1 bash -c 'kinit -kt /root/test1.keytab test1 && hdfs haadmin -ns ns6789 -getServiceState nn1 && hdfs haadmin -ns ns6789 -getServiceState nn2'
```

> `haadmin` 需要 Kerberos 票据：先 `kinit -kt /root/test.keytab test`（或对应测试用户）。

## 2. 通过 nameservice 访问（走故障转移代理）

```bash
docker exec namenode-a1 bash -c 'kinit -kt /root/test.keytab test && hdfs dfs -mkdir -p hdfs://ns1234/user/test && hdfs dfs -ls hdfs://ns1234/user'
```

无论当前 active 是 nn1 还是 nn2，客户端都会自动路由到 active，无需指定具体 NN。

## 3. 跨域访问（双 KDC 互信）

```bash
# test@EMR.1234.COM 访问集群 B
docker exec namenode-a1 bash -c 'kinit -kt /root/test.keytab test && hdfs dfs -ls hdfs://nn1.emr.6789.com:9000/user'

# test1@EMR.6789.COM 访问集群 A
docker exec namenode-b1 bash -c 'kinit -kt /root/test1.keytab test1 && hdfs dfs -ls hdfs://nn1.emr.1234.com:9000/user'
```

## 4. 手动故障转移（演练 ZKFC 自动接管）

```bash
# 查看当前 active
docker exec namenode-a1 bash -c 'kinit -kt /root/test.keytab test && hdfs haadmin -ns ns1234 -getServiceState nn1'

# 假设 nn1 是 active：停止 nn1 模拟故障
docker stop namenode-a1

# 等待 ~15 秒后，nn2 应自动接管
docker exec namenode-a2 bash -c 'kinit -kt /root/test.keytab test && hdfs haadmin -ns ns1234 -getServiceState nn2'
# 期望输出：active

# 代理访问不受影响（自动切到 nn2）
docker exec namenode-a2 bash -c 'hdfs dfs -ls hdfs://ns1234/user'

# 恢复：重启 nn1，应自动以 standby 身份回归
docker start namenode-a1
sleep 30
docker exec namenode-a2 bash -c 'kinit -kt /root/test.keytab test && hdfs haadmin -ns ns1234 -getServiceState nn1'
# 期望输出：standby
```

## 5. 查看 ZKFC 与 JournalNode 日志

```bash
docker logs namenode-a1 | grep -iE "zkfc|active|standby" | tail -20   # 故障转移轨迹
docker logs jn1 | tail -20                                           # QJM 编辑日志写入
```

## 6. 数据一致性验证（故障转移后读数据）

```bash
# 故障前写入一个文件
docker exec namenode-a1 bash -c 'kinit -kt /root/test.keytab test && echo hello-ha | hdfs dfs -put - hdfs://ns1234/user/test/ha.txt'

# 故障转移后（nn1 已停）从 nn2 读取
docker exec namenode-a2 bash -c 'hdfs dfs -cat hdfs://ns1234/user/test/ha.txt'
# 期望输出：hello-ha
```
